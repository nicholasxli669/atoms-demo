## 1. 实现思路与关键取舍

### 1.1 整体链路

```
浏览器 ──SSE──▶ client (Next.js BFF) ──SSE──▶ server (FastAPI Agent) ──流式──▶ LLM
                     │                              │
                     │                              └─ 规划 / 生成 / 静态校验 / 自动修复 / 续写
                     └─ 项目·消息·版本落库（SQLite / libSQL）
```

Agent 服务**无状态**：不碰数据库、不落文件，只吐事件；落库、版本号、消息写入全部由 client 负责。这样 Agent 可以独立部署和扩缩，也让「谁负责持久化」这件事只有一个答案。

两端之间用 `packages/contract/` 里的 SSE 事件契约约束，并附 `check_contract.py` 做**可执行的契约自检**（不是一篇文档，跑一次就知道有没有违约）。

### 1.2 关键取舍

| 决策 | 选了 | 否掉了 | 为什么 |
|---|---|---|---|
| 服务拆分 | client(BFF) + server(Agent) + contract | 单进程一把梭 | 单文件里调模型、管 SSE、落库、记版本，改一处会牵动全部；拆开后 Agent 无状态可独立扩缩，契约让两端能各自演进 |
| Agent 框架 | **FastAPI** | Flask / Django REST / 裸 Starlette | 主链路是「长连接流式」：`pipeline` 本身就是 async generator，`StreamingResponse` 直接 `async for` 吐出去，零适配；Flask 同步 WSGI 下做 SSE 要引 gevent 或线程，恰好踩在最依赖的机制上；Django 的 ORM/admin 我们一个都用不上 |
| LLM 客户端 | **httpx 直连** OpenAI 兼容协议 | openai SDK | 只用一个 HTTP 协议，少一层依赖和版本约束，流式解析 30 行就能写完 |
| 生成物形态 | **单文件 HTML**（内联 CSS/JS） | React/Vue 工程产物 | iframe 秒级预览、零构建、下载即用、模型输出最稳。代价见 §2.2 |
| 质量保障 | **确定性静态校验 + 自动修复** | 让模型自评「我写好了」 | 模型自评不可信。用结构判据硬卡（doctype/闭合/标签配对/体积），不过就带 issue 列表重写，最多 2 轮；最终仍不过则在消息里显式标 ⚠，不把残缺版本包装成成功 |
| 输出上限应对 | **尾部续写** | 提高 token 上限 / 截断丢弃 | 单次输出有硬上限。检测到没有 `</html>` 就把末尾 4000 字符给模型续写，拼接后再校验，最多 2 次 |
| 持久化 | `node:sqlite`（WAL）→ 可切 libSQL/Turso | 直接上 Postgres / 纯 JSON 文件 | 本地零配置，同一套 Store 接口在线上切托管 SQL；JSON 文件无事务（删项目要级联三表） |
| 部署形态 | 阿里云 ECS（单机双服务） | 函数计算 FC / SAE | SQLite 需要持久磁盘，FC 上文件会被销毁；换 Serverless 要先改存储层，超出作业范围 |
| 可用性兜底 | `AGENT_URL` 不通则回落内置 TS 流水线 | 只留一条路 | 评审环境可能只起 client、或者不配模型 Key：前者自动回落、后者走离线模板，保证任何环境点开都有东西看 |

## 2. 当前完成程度

### 2.1 已完成

- **生成主链路**：需求 → 规划（产品经理）→ 流式生成（工程师）→ 静态校验（QA）→ 自动修复 → 落版本
- **增量修改**：同一项目内继续提要求，基于上一版完整源码改写，生成 `v1→v2→v3`，历史保留可回滚
- **运行期闭环**：预览 iframe 注入 console/error 桥，把运行时错误回传工作台，一键让 Agent 修复（这是本作业的延展能力）
- **质量验收报告**：每轮生成后出一张体检卡——7 项静态判据（DOCTYPE / `</html>` 闭合 / `<body>` / 标签配对 / 体积 / localStorage / 零外链）逐项打勾、自动修复轮次与续写次数、行数字节耗时；报告随消息落库，刷新后历史版本也看得到
- **数据持久化**：SQLite 三表（projects / messages / versions）+ 完整源码入库；删除项目为事务级联
- **工程基建**：client 17 个单测（校验/体检报告/文案/store 并发）、server 15 个单测、lint 0 error、build 通过、SSE 契约自检脚本
- **无 Key 可演示**：内置离线模板，评审机器没有模型 Key 也能走完界面流程
- **响应式**：1440 三栏 / 390 单栏 + 底部切换，均无横向滚动

### 2.2 已知边界（明确没做，不粉饰）

1. **预览沙箱不是安全边界**：iframe 用 `allow-scripts + allow-same-origin`（为了让生成应用能用 localStorage），理论上生成物可以碰到宿主页面。这是演示沙箱，**不能用于不可信输入**。
2. **无 CSP、无禁用 API 清单**：`eval`、`document.cookie`、`window.open`、外链 `fetch` 目前都不拦（外链只算 warn）。
3. **无 prompt 注入防护**：上一版生成物会作为上下文回灌给模型，存在自我投毒路径。
4. **双份校验实现**：`validate.ts` 与 `validate.py` 是两套代码，靠人工对齐 + 契约检查，**没有跨语言 golden case**（同一个样本喂两边必须同结论）。
5. **整文件重写而非 diff**：文件越大越吃 token，>900 行会频繁触发续写；Agent 不读历史对话，只用「当前源码 + 这条指令」。
6. **单实例约束**：SQLite 单写者；同项目并发已加进程内 409 锁，多副本部署要换 Redis/DB 锁。
7. **无鉴权**（题目不要求）、无 DB migration、无多租户。

### 2.3 实测数据

| 场景 | 结果 |
|---|---|
| 首轮生成 | 578 行 / 13.7 KB / 14.9s，静态校验 0 问题 |
| 三轮连续改版 | 20.3s（v1，19.3KB）→ 22.3s（v2，24.3KB）→ 74.2s（v3，27.9KB，含 2 次 QA 失败修复 + 1 次续写） |
| 并发保护 | 同项目同时发两轮：一个 `200` 流 + 一个 `409`，只落 1 个版本 |
| 测试 | client 13 passed / server 15 passed / lint 0 / build 6 路由 |
| 浏览器 | 0 个阻断性 JS 错误；预览内提交表单后 localStorage 持久化，刷新仍在 |

## 3. 如果继续投入时间，会怎么扩展

判断标准只有一条：**这个改动是让「已交付的东西更可信」，还是让「产品更有价值」**。前者不依赖任何外部确认、成本可控，先做；后者需要真实用户反馈来验证，排后面。

**P0 · 补齐可交付性（评审前必须完成）**
- 在线 Demo 地址 + public 源码仓库 —— 没有链接，其他维度都无从验证

**P1 · 正确性与安全（1~2 天，不依赖产品判断）**
1. **跨语言 golden case**：一份 JSON 样本清单，`validate.ts` 和 `validate.py` 各跑一遍，逐条断言结论一致。这是当前架构最脆的地方，一次投入长期免疫。
2. **预览真隔离**：把预览挪到独立 origin，`allow-same-origin` 保留但拿不到宿主；或去掉它并注入 localStorage 代理。
3. **校验器加禁用 API + 注入 CSP**：`eval` / `document.cookie` / `window.open` / 外链 `fetch` 直接判 error 触发修复轮。
4. **DSL 层的输出白名单**：在 CSP 之外，对 `<script>` 内容做一次静态扫描。

**P2 · 产品价值（需要验证再投入）**
1. **多文件工程产物**：生成可运行的 React/Vue 项目而非单文件，突破 token 与体量天花板 —— 但这会牺牲「秒级预览」，需要先确认用户更在意哪个。
2. **需求确认后再写码**：现在一句话直接生成，返工率高；改成「先出需求 checklist → 用户确认 → 再写代码」，可能比多生成几次更省。
3. **流式 diff**：整文件重写改成增量补丁，省 token 也减少功能漂移。
4. **一键部署生成的应用**：生成完直接给一个可分享链接，把「工作台」变成「发布台」。
5. **分享/协作**：项目链接、版本对比视图。

## 4. 本地运行

```bash
# 1) 装依赖
npm --prefix client install
cd server && uv venv .venv && uv pip install -r requirements.txt && cd ..

# 2) 配置（两边都要有 Key；不配也能跑，会走离线模板）
cp client/.env.example client/.env.local     # 填 DEEPSEEK_API_KEY
cp server/.env.example server/.env           # 填 DEEPSEEK_API_KEY
# Windows PowerShell 用：
#   Copy-Item client\.env.example client\.env.local
#   Copy-Item server\.env.example server\.env
# 注意：PowerShell 5.1 的 `Set-Content -Encoding utf8` 会写 BOM，存 .env 请用记事本/VSCode 存成 UTF-8 无 BOM

# 3) 起服务（两个终端，或分别后台）
npm run dev:server     # FastAPI Agent  → http://127.0.0.1:8100
npm run dev            # Next.js 工作台 → http://localhost:3000

# 校验
npm test               # client 单测
npm run test:server    # server 单测
npm run contract       # SSE 契约自检（需要 server 在跑）
```

### 目录结构

```
client/     Next.js 工作台 + BFF：SSE 转发、项目/消息/版本落库
server/     FastAPI Agent：规划 / 生成 / 校验 / 修复 / 续写（无状态）
packages/contract/   SSE 事件契约 + check_contract.py
docs/       部署文档（阿里云 ECS）、交付说明
scripts/    pack.mjs（打包）、install-ecs.sh（一键部署）、py.mjs（venv 启动器）
```
